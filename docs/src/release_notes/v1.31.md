# Release notes for CloudNativePG 1.31

History of user-visible changes in the 1.31 minor release of CloudNativePG.

For a complete list of changes, please refer to the
[commits](https://github.com/cloudnative-pg/cloudnative-pg/commits/release-1.31)
on the release branch in GitHub.

## Version 1.31.0-rc1

**Release date:** Nov 25, 2026

### Important changes

- **`CONNECT` is revoked from `PUBLIC` on the databases created by the
  operator**: new clusters and new databases are now closed by default. The
  operator revokes `CONNECT` from `PUBLIC` on `postgres`, `template1`, and the
  application database of a cluster bootstrapped with `initdb`, and on every
  database created from a `Database` resource. The `cnpg_metrics_exporter` role
  keeps `CONNECT` on all of them, so monitoring continues to work, and the
  `streaming_replica` role is granted `CONNECT` on `postgres`. Other roles, such
  as managed ones, need to own the database or be granted `CONNECT`, for example
  with the `spec.permissions` of a `Database`. Existing databases are never
  changed, so upgrading the operator or recovering a cluster doesn't alter any
  privileges.
  ([#11976](https://github.com/cloudnative-pg/cloudnative-pg/pull/11976))

- **`automountServiceAccountToken` is disabled on instance Pods**: the
  operator now unconditionally sets `automountServiceAccountToken: false` on
  instance Pods, instance creation `Job`s (including major upgrade), and the
  `ServiceAccount` it generates, so that clusters comply out of the box with
  admission policies forbidding the automatic mounting of the token. The
  operator projects an explicit `kube-api-access` volume on the containers
  that need access to the Kubernetes API. `ServiceAccount`s supplied through
  `serviceAccountName` are left untouched. Clusters upgrading from a previous
  release go through a one-time rolling update.
  ([#11115](https://github.com/cloudnative-pg/cloudnative-pg/pull/11115))

- **Default `smartShutdownTimeout` is now 0 seconds**: the default of
  `.spec.smartShutdownTimeout` changed from 180 to 0, so new clusters skip the
  smart shutdown phase and request a fast shutdown (still preceded by a
  `CHECKPOINT`) as soon as a PostgreSQL Pod is terminated. The smart phase
  waits for clients to disconnect and rarely completes with long-lived
  application and pooler connections, delaying node drains and rolling
  updates. Existing clusters keep the value already persisted in their spec;
  set `.spec.smartShutdownTimeout` to `180` explicitly to keep the previous
  behavior. See "Upgrading to 1.31.0" in the documentation.
  ([#11944](https://github.com/cloudnative-pg/cloudnative-pg/pull/11944))

- **The legacy synchronous replication configuration is deprecated**: the
  method based on `.spec.minSyncReplicas`, `.spec.maxSyncReplicas`, and
  `.spec.postgresql.syncReplicaElectionConstraint` is deprecated starting from
  1.31 and will be removed in 1.33.0. The admission webhook now warns when a
  cluster uses these fields. Migrate to `.spec.postgresql.synchronous`. For the
  same reason, the `min` and `max` values of the `cnpg_collector_sync_replicas`
  metric are deprecated and will be removed in 1.33.0.
  ([#11978](https://github.com/cloudnative-pg/cloudnative-pg/pull/11978), [#11990](https://github.com/cloudnative-pg/cloudnative-pg/pull/11990))

- **Instances are bootstrapped by an init container, not a Job**: new primary
  and replica instances (`initdb`, recovery, `pg_basebackup`, join, and
  snapshot restore) are now bootstrapped directly in the instance Pod through
  an init container, instead of by a separate Kubernetes `Job` run beforehand.
  This removes the extra `Job` and Pod created for every new instance, and the
  wait for that `Job` to complete. A stuck bootstrap is now reported as
  `PhaseUnrecoverable` in the `Cluster` status, and a replica resuming a
  stalled bootstrap reports `PhaseCreatingReplica` with an event. Tooling
  that watches the bootstrap `Job`s must be updated.
  ([#11319](https://github.com/cloudnative-pg/cloudnative-pg/pull/11319))

- **Online volume snapshot backups no longer include the WAL volume**: an
  online volume snapshot backup of a cluster with a dedicated WAL volume
  (`.spec.walStorage`) now snapshots only `PGDATA` and the tablespaces, as
  recovering an online backup requires the WAL archive anyway. Restoring such
  a backup creates an empty WAL volume and fetches the WAL files from the
  archive, so the recovery needs a `source` that points to a working WAL
  archive. Cold backups still include the WAL volume, and existing backups are
  not affected.
  ([#11734](https://github.com/cloudnative-pg/cloudnative-pg/pull/11734))

- **The status port always uses TLS**: all instances have used TLS for
  operator communication since 1.24, so the HTTP fallback has been removed.
  This affects you only if some Pods were created by an operator older than
  1.24: in that unlikely case, perform a manual rolling update of those Pods
  to recreate them with a TLS-enabled status port. The `--status-port-tls`
  flag is still set on instance Pods, but is ignored by the instance manager;
  it only lets `kubectl cnpg` versions older than 1.31 detect TLS.
  Contributed by @GellertBabel.
  ([#11370](https://github.com/cloudnative-pg/cloudnative-pg/pull/11370), [#11946](https://github.com/cloudnative-pg/cloudnative-pg/pull/11946))

### Features

- **PostgreSQL 19 support**: added support for PostgreSQL 19, released on
  November 19, 2026. The default operand image for new clusters that don't set
  an image is now `19.0-system-trixie`. Existing clusters keep their current
  image.
  ([#11936](https://github.com/cloudnative-pg/cloudnative-pg/pull/11936))

- **Smoother failover and switchover around the primary `Lease`**: building
  on the primary `Lease` introduced in 1.30.0, failover and switchover are
  faster, more predictable, and easier to follow.

    - *Failover:*
        - Started the primary lease window of a replica at the pending
          failover marker, so that a failover no longer waits for the lease
          duration on top of the election.
          ([#11798](https://github.com/cloudnative-pg/cloudnative-pg/pull/11798))
        - Tried a fast shutdown first when a primary steps down because it
          cannot renew its lease, falling back to an immediate shutdown if it
          does not complete in time. This lets the remaining WAL reach the new
          primary when only the API server was unreachable.
          ([#11805](https://github.com/cloudnative-pg/cloudnative-pg/pull/11805))
        - Moved the primary isolation check onto the primary lease, so that
          the reaction time of an isolated primary follows the time a replica
          waits before promoting, instead of the liveness probe periods.
          ([#11357](https://github.com/cloudnative-pg/cloudnative-pg/pull/11357))
        - Detected a replica that diverged from the timeline of the primary,
          which can happen when a replica that is not the most advanced one is
          promoted. The replica is kept out of the read services, of the
          election, and of the failover quorum, and is reported in the new
          `divergedInstances` status field, in the `ReplicasHealthy` condition,
          in a `ReplicaDiverged` event, and in the
          `cnpg_collector_replicas_diverged` metric. The operator then fences
          the instance and drops its replication slot on the primary.
          ([#11251](https://github.com/cloudnative-pg/cloudnative-pg/pull/11251))
        - Avoided starting a failover when all the Pods of a cluster are
          deleted at once: the current primary is allowed to start again, and a
          pending failover is canceled, with a `FailoverCancelled` event.
          ([#11940](https://github.com/cloudnative-pg/cloudnative-pg/pull/11940))
        - Made a replica that is no longer the target primary release the
          primary lease, so that the new target can take it over promptly.
          ([#11677](https://github.com/cloudnative-pg/cloudnative-pg/pull/11677))
        - Made a primary stop when a peer reports that another instance has
          been named target primary, even when the primary isolation check is
          disabled.
          ([#11795](https://github.com/cloudnative-pg/cloudnative-pg/pull/11795))
        - Turned the liveness probe into a watchdog, so that the kubelet
          recreates a Pod whose primary lease loop is no longer making
          progress, or whose PostgreSQL does not stop on an immediate
          shutdown.
          ([#11358](https://github.com/cloudnative-pg/cloudnative-pg/pull/11358))

    - *Switchover:*
        - Published the position of the primary on the primary lease, in the
          `cnpg.io/position` annotation (LSN, timeline, instance state, and
          Pod), and made a promoting replica mark the lease as `promoting`.
          ([#11885](https://github.com/cloudnative-pg/cloudnative-pg/pull/11885))
        - Made a switchover wait until the new primary has all the data
          published by the previous primary on its lease. If the candidate is
          still catching up, for example while WAL is being fetched from the
          archive, it waits and then promotes as soon as it is ready. The
          status is reported in the instance log and in a `PromotionHeldBack`
          event on the `Cluster`, together with the available options: wait,
          remove the `cnpg.io/position` annotation from the lease to promote
          without waiting, or cancel the switchover with
          `kubectl cnpg promote --force`. Failovers, and cases where the
          position is unknown, are not affected.
          ([#11932](https://github.com/cloudnative-pg/cloudnative-pg/pull/11932))
        - `cnpg` plugin: made `promote` aware of a switchover in progress,
          which it no longer modifies by accident. To go back to the previous
          primary, use `kubectl cnpg promote --force <cluster> <current primary>`
          to cancel the switchover.
          ([#11956](https://github.com/cloudnative-pg/cloudnative-pg/pull/11956))

- **Export logs via OpenTelemetry without a DaemonSet**: the operator, the
  instance manager, and the PgBouncer instance manager can now push their logs
  via OTLP (gRPC or HTTP, with TLS and headers) directly to an OpenTelemetry
  collector, with no DaemonSet or sidecar to collect them. The export is
  enabled with the standard `OTEL_*` environment variables, read from the
  operator `Deployment`, from the `env` and `envFrom` of a `Cluster` (so each
  cluster can use its own collector), and from the Pod template of a `Pooler`.
  PostgreSQL and PGAudit records are exported as structured attributes, the
  configured log level is honored, the standard output is unchanged, and the
  export never slows down PostgreSQL: records the collector cannot keep up
  with are dropped, and the queue is flushed before exiting.
  ([#11783](https://github.com/cloudnative-pg/cloudnative-pg/pull/11783))

- **In-place resource resizing of instance Pods**: a new
  `spec.resourcesUpdateStrategy` field accepts `recreate` (the default) or
  `inPlace`. With `inPlace`, when the only drift in a running Pod is in the
  container resources, the operator resizes the Pod through the `pods/resize`
  subresource instead of deleting it: nothing restarts, the primary needs no
  switchover, and a resized Pod takes no rollout slot. The Pod is recreated
  when the change cannot be applied in place. `inPlace` requires Kubernetes
  1.33 or later.
  ([#11116](https://github.com/cloudnative-pg/cloudnative-pg/pull/11116))

- **Failure domain-aware synchronous replication**: added the mutually
  exclusive `podFailureDomainKeys` and `nodeFailureDomainKeys` options to
  `.spec.postgresql.synchronous`, restricting the selection of synchronous
  standbys to instances in a failure domain (such as an availability zone)
  different from the primary's, so that a single-zone outage cannot take out
  the primary and all its synchronous replicas at once. The constraint applies
  only when it can be fully satisfied; otherwise the operator falls back to
  the regular selection.
  ([#11144](https://github.com/cloudnative-pg/cloudnative-pg/pull/11144))

- **Generated passwords for declarative roles**: a `DatabaseRole` can now
  include a `password` stanza so that the operator generates the password
  instead of requiring a pre-existing `Secret`. The password is stored in a
  `kubernetes.io/basic-auth` `Secret` (named `<databaserole-name>-password` by
  default), with configurable generation criteria, `duration`, and
  `renewBefore` for automatic rotation.
  ([#11337](https://github.com/cloudnative-pg/cloudnative-pg/pull/11337))

- **Database privileges in the `Database` resource**: a new `spec.permissions`
  stanza grants and revokes the `CONNECT`, `CREATE`, and `TEMPORARY`
  privileges on a database declaratively, instead of running SQL scripts after
  the database is created. This covers the common hardening setup of revoking
  `CONNECT` from `public` and granting it back to specific roles. The operator
  reads the privileges currently held and runs a `GRANT` or `REVOKE` only when
  needed, reporting the outcome in the status.
  ([#11906](https://github.com/cloudnative-pg/cloudnative-pg/pull/11906))

- **Schema privileges in the `Database` resource**: schema entries in the
  `Database` CRD accept a new `permissions` field to declaratively grant or
  revoke the `USAGE` and `CREATE` privileges on a schema, alongside the
  existing `owner` and `ensure` management.
  Contributed by @BRGOVIND.
  ([#10910](https://github.com/cloudnative-pg/cloudnative-pg/pull/10910))

### Enhancements

- Changed the `observed` value of the `cnpg_collector_sync_replicas` metric to
  count the standbys actually attached to the primary in the `sync` or
  `quorum` state, instead of the number requested in
  `synchronous_standby_names`, so that `observed < expected` is the condition
  to alert on.
  ([#11990](https://github.com/cloudnative-pg/cloudnative-pg/pull/11990))

- Added an admission webhook warning when a multi-instance cluster has no
  synchronous replication configured, to make the durability trade-off of
  asynchronous replication visible when the cluster is applied.
  ([#11148](https://github.com/cloudnative-pg/cloudnative-pg/pull/11148))

- Added `spec.bootstrap.pg_basebackup.additionalArgs` to append custom
  arguments (for example `--max-rate` or `--checkpoint`) to the
  `pg_basebackup` command built by the operator.
  ([#11595](https://github.com/cloudnative-pg/cloudnative-pg/pull/11595))

- Added `spec.bootstrap.pg_basebackup.tablespaceMapping` to clone a source
  instance whose tablespaces are not in the CloudNativePG location, by mapping
  each tablespace declared in `spec.tablespaces` to its source path.
  ([#11649](https://github.com/cloudnative-pg/cloudnative-pg/pull/11649))

- Added optional `duration` and `renewBefore` fields to the `clientCertificate`
  stanza of a `DatabaseRole`, so that each role can have its own certificate
  lifetime and renewal window instead of the operator-wide
  `CERTIFICATE_DURATION` and `EXPIRING_CHECK_THRESHOLD` values.
  ([#11342](https://github.com/cloudnative-pg/cloudnative-pg/pull/11342))

- Added a reviewed set of editor roles for automation: `cnpg-editor-role`, an
  aggregate role for the namespaced resources, plus the `ImageCatalog`,
  `ClusterImageCatalog`, and `DatabaseRole` editor roles, with documentation
  on the opt-in aggregation into the built-in `edit` and `admin` roles.
  ([#11784](https://github.com/cloudnative-pg/cloudnative-pg/pull/11784))

- Added the `cnpg-viewer-role` `ClusterRole`, with read-only access to the
  CloudNativePG, Barman Cloud, and Klio API groups, and documented read-only
  DBA personas with sample `RoleBinding`s.
  ([#11684](https://github.com/cloudnative-pg/cloudnative-pg/pull/11684))

### Security and Supply Chain

- Signed each architecture-specific manifest of the multi-architecture
  container images with Cosign, in addition to the multi-architecture index.
  ([#11971](https://github.com/cloudnative-pg/cloudnative-pg/pull/11971))

- Documented that a user who can write `DatabaseRole` objects can have the
  instance `ServiceAccount` read any `Secret` of the namespace whose name they
  know, through `password.secret`, and that this access should be granted
  accordingly.
  ([#12010](https://github.com/cloudnative-pg/cloudnative-pg/pull/12010))

### Fixes

- Left volumes that already hold an instance untouched when the
  `bootstrap-instance` init container runs again, for example when a backup
  tool restores a Pod together with its PVCs. The container now runs only
  when the operator has marked the bootstrap as pending.
  ([#11608](https://github.com/cloudnative-pg/cloudnative-pg/pull/11608))

- Fixed instances stuck forever with a provisioned PVC but no bootstrap
  `Job`: the `Job` is now recreated for every instance, not only for the first
  primary.
  ([#11142](https://github.com/cloudnative-pg/cloudnative-pg/pull/11142))

- Stopped the orphan-PVC restore gate from waiting on the operator's own
  init containers, which prevented stale Pods restored by a backup tool from
  being deleted.
  ([#11549](https://github.com/cloudnative-pg/cloudnative-pg/pull/11549))

- Kept a PVC in the initializing state until its bootstrap container reports
  its status.
  ([#11801](https://github.com/cloudnative-pg/cloudnative-pg/pull/11801))

- Stopped a shutdown from signaling an unrelated process when a leftover
  `postmaster.pid` names a PID that is alive but is not PostgreSQL.
  ([#11992](https://github.com/cloudnative-pg/cloudnative-pg/pull/11992))

- Fixed the `min` and `max` values of the `cnpg_collector_sync_replicas`
  metric, which were reported as 0 for clusters configured through
  `.spec.postgresql.synchronous`.
  ([#11979](https://github.com/cloudnative-pg/cloudnative-pg/pull/11979))

### Supported versions

- Kubernetes 1.37, 1.36, and 1.35
- PostgreSQL 19, 18, 17, 16, and 15
    - PostgreSQL 19.0 (`19.0-system-trixie`) is the default image
    - PostgreSQL 15 support ends on November 11, 2027
